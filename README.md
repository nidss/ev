# EV — Event Management Platform

ระบบจัดงานสำหรับงานคนจำนวนมาก (ไทย + ต่างชาติ): ลงทะเบียน เช็คอินหน้างาน และเก็บ lead ให้ผู้ออกบูธ ด้วย QR และสายรัดข้อมือ RFID
โดยแชร์ข้อมูลเฉพาะคนที่ยินยอมตาม PDPA

งานตัวอย่างตอนนี้คือ **MOC Expo 2026** — งานแสดงและจำหน่ายสินค้า พร้อมกิจกรรมส่งเสริมผู้ประกอบการ ของกระทรวงพาณิชย์
**ลงทะเบียนฟรี** แล้วได้ป้ายชื่อ: ด้านหน้า = ชื่อ บริษัท QR, ด้านหลัง = ผังงานแบ่งสีตามหมวดสินค้า
(วันที่ สถานที่ หมวดสินค้า และรายชื่อผู้ออกบูธยังเป็นข้อมูลตัวอย่าง — แก้ได้ที่ `packages/core/src/mock-data.ts`)

**เปิดดู (public):** https://nidss.github.io/ev/

## แอป (`apps/web`, `packages/core`)

Prototype แบบ static (Next.js `output: "export"`) ขึ้น GitHub Pages — **ทุกอย่างรันในเบราว์เซอร์** ไม่มี server
business logic ทั้งหมดอยู่ใน `packages/core` (ชุดเดียวกับที่จะใช้บน server จริง) ส่วน API จำลองอยู่ใน `apps/web/src/lib/local-api.ts`
งาน MOC Expo ลงทะเบียนฟรีทั้งหมด (ผู้เข้าชมทั่วไป / ผู้ประกอบการ-ผู้ซื้อ Trade / สื่อมวลชนที่ต้องใช้โค้ด) ใช้ได้ทุกวันของงาน
engine ยังรองรับบัตรเสียเงิน workshop add-on โค้ดส่วนลด และ payment gateway จำลอง — ข้อมูลชุดนั้นย้ายไปเป็น test fixture
(`packages/core/test/fixtures/paid-catalog.ts`) ดู [docs/TICKETING.md §12](docs/TICKETING.md#12-ราคาบัตร-mock-ใช้ใน-prototype)

```
apps/web/          Next.js 16 (App Router, static export) — หน้าเว็บทุกบทบาท + API จำลองในเบราว์เซอร์
packages/core/     business logic: ราคา, จองที่นั่ง, order, webhook, mock payment, QR,
                   เช็คอิน (กฎใช้ร่วมกับเครื่องสแกนออฟไลน์), lead, sponsor, dashboard (+ unit test)
```

| บทบาท | หน้า | ทำอะไรได้ |
|---|---|---|
| ทุกคน | `/` | หน้ารวมลิงก์ตามบทบาท |
| ผู้เข้างาน | `/e/<slug>` → `/checkout?order=` → `/t?order=` | เลือกประเภทผู้เข้างานบนหน้างาน → กรอกข้อมูล → ยืนยัน → ได้ป้ายชื่อ (หน้า QR / หลังผังงาน) พิมพ์ได้ |
| ผู้เข้างานที่บูธ | `/b/<qrSlug>` | สแกน QR บูธด้วยกล้องมือถือ → ยืนยันตัวด้วยรหัสบัตร + อีเมลครั้งเดียว → กด "สนใจ" / "ขอข้อมูลเพิ่ม" |
| Staff ประตู | `/org/<slug>/checkin` | สแกน QR (เครื่องยิงบาร์โค้ด / กล้อง / พิมพ์รหัส), ค้นชื่อ, ตรวจเอกสารบัตร Press, ผูกสายรัด RFID, พิมพ์ป้ายชื่อ, จำลองเน็ตหลุดแล้ว sync |
| Staff บูธ | `/booth/<boothId>` | สแกนป้ายชื่อ / แตะสายรัด → ให้คะแนน hot/warm/cold + โน้ต |
| ผู้ออกบูธ | `/sponsor/<sponsorId>` | ดู lead เฉพาะคนที่ยินยอม, สถิติบูธ, export CSV (บันทึกทุกครั้งเป็นหลักฐาน PDPA) |
| ผู้จัดงาน | `/org/<slug>` | Dashboard อัปเดตทันที (รวมจากแท็บอื่น), รายชื่อ + ค้นหา, QR ประจำบูธ |

### ข้อมูลอยู่ที่ไหน

- เปิดครั้งแรก เบราว์เซอร์สร้างข้อมูลตัวอย่างเอง (ชื่อสมมติ ~180 การลงทะเบียน, การเช็คอินและการเข้าบูธของวันแรก) แล้วเก็บใน **localStorage**
- **ทุกแท็บในเบราว์เซอร์เดียวกันใช้ข้อมูลชุดเดียวกัน** — เปิดแท็บเช็คอินกับแท็บ dashboard คู่กัน ตัวเลขอัปเดตทันที
- **คนละเครื่อง / คนละเบราว์เซอร์ = ข้อมูลคนละชุด** เช่น สแกน QR บูธด้วยมือถือจะเปิดข้อมูลชุดของมือถือ (รหัสบัตรที่ลงทะเบียนบนคอมจะหาไม่เจอ) — ถ้าจะลองบนเครื่องเดียวให้กดปุ่ม "QR →" ในหน้า "บูธและ QR" แทน
- ปุ่ม "ล้างข้อมูลและสร้างข้อมูลตัวอย่างใหม่" อยู่ท้ายหน้าแรก
- หน้า staff / ผู้ออกบูธ / ผู้จัดยังไม่มีระบบ login — เป็นข้อมูลสมมติทั้งหมด ห้ามใส่ข้อมูลจริง

สิ่งที่หน้างานทำได้จริง:

- **QR บัตรมีลายเซ็น Ed25519** (`@noble/ed25519`) — QR ปลอมหรือถูกแก้ถูกปฏิเสธ ออกบัตรใหม่แล้ว QR เก่าใช้ไม่ได้ เครื่องสแกนตรวจลายเซ็นเองได้ด้วย public key
- **Offline check-in** — ติ๊ก "จำลองเน็ตหลุด" เครื่องใช้รายชื่อที่โหลดไว้ ตัดสินผลด้วยกฎชุดเดียวกับ backend แล้วเก็บคิว กลับมาออนไลน์ก็ sync ทันที ส่งซ้ำได้ไม่เกิดข้อมูลซ้ำ
- **กฎเช็คอิน** — ผ่านได้วันละครั้งต่อจุด, โซน Business Matching เข้าได้เฉพาะ Trade / Press, บัตร Press ต้องให้ staff ยืนยันว่าตรวจเอกสารแล้ว (engine ยังรองรับบัตรรายวันและห้อง workshop)
- **ผังงาน** — โซนสินค้าระบายสีตามหมวด (A–F) มีตัวอักษรและชื่อกำกับทุกโซน รหัสบูธขึ้นต้นด้วยตัวอักษรของหมวด แสดงบนหน้างานและด้านหลังป้ายชื่อ
- **PDPA** — ผู้ออกบูธและ staff บูธเห็นตัวบุคคลเฉพาะคนที่ยินยอม คนที่ไม่ยินยอมนับเป็น traffic เท่านั้น, CSV กัน formula injection

ต้องมี Node 22+ และ pnpm 10

```bash
pnpm install
pnpm dev            # http://localhost:3000 → หน้ารวมลิงก์ตามบทบาท
pnpm test           # unit test ของ packages/core
pnpm typecheck
pnpm build          # static site ที่ apps/web/out
```

ขั้นตอนลงทะเบียน: หน้างาน → ① เลือกประเภทผู้เข้างาน + จำนวนคน + ยอมรับเงื่อนไข → ② กรอกข้อมูล → ③ ตรวจสอบแล้วยืนยัน → ได้ป้ายชื่อ

ลองใช้:

1. หน้างาน → **ผู้เข้าชมงานทั่วไป** +1 และ **ผู้ประกอบการ / ผู้ซื้อ (Trade)** +1 → ติ๊กยอมรับเงื่อนไข → ลงทะเบียน → กรอกข้อมูล 2 คน → ยืนยัน → ได้ป้ายชื่อ 2 ใบ กด "พิมพ์ป้ายชื่อ" (10 × 14 ซม. ใบละ 2 หน้า)
2. ใส่โค้ด `PRESS2026` ในช่อง "มีโค้ดจากผู้จัด?" → ประเภทสื่อมวลชน (ซ่อน) จะโผล่ขึ้นมา
3. ปุ่มมุมขวาบนสลับภาษา ไทย / English
4. จดรหัสบัตรจากป้ายชื่อ → **Staff เช็คอิน** เลือก "ประตู 1" → พิมพ์รหัสบัตร Enter → ผ่าน → กด "จำลองแตะสายรัด" → สแกนซ้ำ → "เข้าไปแล้ว"
5. เปลี่ยนจุดเช็คอินเป็น "โซน Business Matching" → ผู้เข้าชมทั่วไปไม่ผ่าน, Trade ผ่าน
6. ติ๊ก "จำลองเน็ตหลุด" → สแกนบัตรอีกใบ (เก็บในเครื่อง) → เอาติ๊กออก → sync อัตโนมัติ
7. **Staff บูธ** (เลือกบูธจากหน้า "บูธและ QR") → สแกนรหัสบัตร → ให้คะแนน Hot + โน้ต → ดูใน **หน้าผู้ออกบูธ** → Export CSV
8. เปิด **ผู้จัดงาน** ค้างไว้อีกแท็บ แล้วเช็คอินจากแท็บแรก → ตัวเลขเข้างาน / กราฟ / บูธ อัปเดตเองทันที

## Deploy

push เข้า `main` แล้ว GitHub Actions (`.github/workflows/pages.yml`) จะรัน test → build static site (`NEXT_PUBLIC_BASE_PATH=/ev`) → deploy ขึ้น GitHub Pages
ต้องตั้ง **Settings → Pages → Source = GitHub Actions** (ครั้งเดียว)

ตอนจะใช้จริงกับงานที่มีหลายเครื่อง (staff หลายจุด + dashboard + ผู้ออกบูธ) ต้องมี server กลาง —
เปลี่ยน `local-api.ts` เป็น API route บน server ที่เรียก `@ev/core` ชุดเดิม และเก็บข้อมูลใน PostgreSQL ตาม [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
