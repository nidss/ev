# EV — Event Management Platform

ระบบจัดงานสำหรับงานคนจำนวนมาก (ไทย + ต่างชาติ): ลงทะเบียน เช็คอินหน้างาน และเก็บ lead ให้ sponsor ด้วย QR และสายรัดข้อมือ RFID
โดยแชร์ข้อมูลเฉพาะคนที่ยินยอมตาม PDPA

## แอป (`apps/web`, `packages/core`)

แอป Next.js ที่มี server จริง ใช้ราคาบัตร mock (มีทั้งบัตรฟรี บัตรเสียเงิน workshop และ add-on) และ payment gateway จำลอง (ไม่มีเงินจริง)
งานนี้ไม่มีผังที่นั่ง — ความจุนับเป็นจำนวนต่อรอบ/ประเภทบัตร รายละเอียดราคาและข้อจำกัดดู [docs/TICKETING.md §12](docs/TICKETING.md#12-ราคาบัตร-mock-ใช้ใน-prototype)

```
apps/web/          Next.js 16 (App Router) — หน้าเว็บทุกบทบาท + API
packages/core/     business logic: ราคา, จองที่นั่ง, order, webhook, mock payment, QR,
                   เช็คอิน (กฎใช้ร่วมกับเครื่องสแกนออฟไลน์), lead, sponsor, dashboard (+ unit test)
```

| บทบาท | หน้า | ทำอะไรได้ |
|---|---|---|
| ทุกคน | `/` | หน้ารวมลิงก์ตามบทบาท |
| ผู้เข้างาน | `/e/<slug>` → `/buy` → checkout → `/t/<order>` | ซื้อบัตร / ลงทะเบียน 5 ขั้น, e-ticket QR |
| ผู้เข้างานที่บูธ | `/b/<qrSlug>` | สแกน QR บูธด้วยกล้องมือถือ → ยืนยันตัวด้วยรหัสบัตร + อีเมลครั้งเดียว → กด "สนใจ" / "ขอข้อมูลเพิ่ม" |
| Staff ประตู | `/org/<slug>/checkin` | สแกน QR (เครื่องยิงบาร์โค้ด / กล้อง / พิมพ์รหัส), ค้นชื่อ, ตรวจเอกสารบัตร Press, ผูกสายรัด RFID, พิมพ์ badge, จำลองเน็ตหลุดแล้ว sync |
| Staff บูธ | `/booth/<boothId>` | สแกน badge / แตะสายรัด → ให้คะแนน hot/warm/cold + โน้ต |
| Sponsor | `/sponsor/<sponsorId>` | ดู lead เฉพาะคนที่ยินยอม, สถิติบูธ, export CSV (บันทึกทุกครั้งเป็นหลักฐาน PDPA) |
| ผู้จัดงาน | `/org/<slug>` | Dashboard อัปเดตทุก 5 วินาที, รายชื่อ + ค้นหา, QR ประจำบูธ |

ตอนเปิด server ระบบสร้างข้อมูลตัวอย่าง (ชื่อสมมติ ~180 คำสั่งซื้อ, การเช็คอินและการเข้าบูธของวันแรก) ให้หน้า dashboard / sponsor มีข้อมูล
ปิดได้ด้วย `SEED_DEMO=0` — **หน้า staff / sponsor / ผู้จัดยังไม่มีระบบ login** ห้ามเปิดให้คนนอกเข้าถึง

สิ่งที่หน้างานทำได้จริง:

- **QR บัตรมีลายเซ็น Ed25519** — QR ปลอมหรือถูกแก้ถูกปฏิเสธ ออกบัตรใหม่แล้ว QR เก่าใช้ไม่ได้ เครื่องสแกนตรวจลายเซ็นเองได้ตอนออฟไลน์ (WebCrypto)
- **Offline check-in** — ติ๊ก "จำลองเน็ตหลุด" เครื่องใช้รายชื่อที่โหลดไว้ ตัดสินผลด้วยกฎชุดเดียวกับ server แล้วเก็บคิว กลับมาออนไลน์ก็ sync ทันที ส่งซ้ำได้ไม่เกิดข้อมูลซ้ำ
- **กฎเช็คอิน** — ผ่านได้วันละครั้งต่อจุด, บัตรรายวันเข้าผิดวันไม่ได้, workshop เข้าได้เฉพาะห้องและวันของตัวเอง, VIP Lounge เฉพาะ VIP / Press, บัตร Press ต้องให้ staff ยืนยันว่าตรวจเอกสารแล้ว
- **PDPA** — sponsor และ staff บูธเห็นตัวบุคคลเฉพาะคนที่ยินยอม คนที่ไม่ยินยอมนับเป็น traffic เท่านั้น, CSV กัน formula injection

ต้องมี Node 22+ และ pnpm 10

```bash
pnpm install
pnpm dev            # http://localhost:3000 → หน้ารวมลิงก์ตามบทบาท
pnpm test           # unit test ของ packages/core
pnpm typecheck
```

ข้อมูลเก็บใน memory — restart server แล้วข้อมูล order/บัตรจะหายหมด

ขั้นตอนซื้อ (แนว ThaiTicketMajor / Zipevent): หน้างาน → ① ยอมรับเงื่อนไข → ② เลือกรอบ (วัน) → ③ เลือกบัตร → ④ กรอกข้อมูล → ⑤ ตรวจสอบและชำระเงิน

ลองใช้:

1. กด **ซื้อบัตร** → ยอมรับเงื่อนไข → เลือกวันเสาร์ → **Expo Pass (ฟรี)** → กรอกข้อมูล → ยืนยัน → ได้ e-ticket QR ทันที
2. กด **ซื้อบัตร** ของรอบวันอาทิตย์ → **Conference Pass + Workshop การเงิน + เสื้อ** → ขั้นชำระเงินใส่โค้ด `WORKSHOP300` → PromptPay → หน้า mock gateway กด "จำลอง: ชำระสำเร็จ"
3. กด "จำลอง: ชำระไม่สำเร็จ" → กลับไปจ่ายใหม่ได้ก่อนหมดเวลา 15 นาที (ข้อมูลที่กรอกไว้ยังอยู่)
4. ขั้นเลือกบัตร ใส่โค้ด `PRESS2026` ในช่อง "มีโค้ดจากผู้จัด?" → บัตร Press Pass (ซ่อน) จะโผล่ขึ้นมา
5. ปุ่มมุมขวาบนสลับภาษา ไทย / English
6. ซื้อ Expo Pass วันเสาร์แล้วจดรหัสบัตร → **Staff เช็คอิน** เลือก "ประตู A" + วันเสาร์ → พิมพ์รหัสบัตร Enter → ผ่าน → กด "จำลองแตะสายรัด" → สแกนซ้ำ → "เข้าไปแล้ว"
7. ติ๊ก "จำลองเน็ตหลุด" → สแกนบัตรอีกใบ (เก็บในเครื่อง) → เอาติ๊กออก → sync อัตโนมัติ
8. **Staff บูธ** (เลือกบูธจากหน้า "บูธและ QR") → สแกนรหัสบัตร → ให้คะแนน Hot + โน้ต → ดูใน **Sponsor portal** ของบูธนั้น → Export CSV
9. **ผู้จัดงาน** → ตัวเลขเข้างาน / กราฟ / บูธ อัปเดตเองทุก 5 วินาที

| ตัวแปร | ค่าเริ่มต้น | ใช้ทำอะไร |
|---|---|---|
| `MOCK_PAYMENT_SECRET` | `dev-mock-secret` | secret สำหรับเซ็น webhook ของ mock gateway |
| `APP_BASE_URL` | (ว่าง = ลิงก์ relative) | URL ที่ gateway จริงใช้พาผู้ซื้อกลับมา และใช้ใน QR บูธ |
| `ATTENDEE_COOKIE_SECRET` | `dev-attendee-cookie-secret` | secret สำหรับเซ็น cookie ยืนยันตัวผู้เข้างานที่บูธ |
| `SEED_DEMO` | (เปิด) | `0` = ไม่สร้างข้อมูลตัวอย่าง |
